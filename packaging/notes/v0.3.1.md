## AstraBridge 0.3.1

### Permanent CLI command

- Added **Enable CLI command** in **Setup → Storage and skill**, plus `cli install`, `cli status` and `cli uninstall`.
- Agents can now use `astrabridge game …` without repeating the AppImage/EXE and configuration paths. Registration is per user and does not require administrator privileges.
- Successful runtime updates switch the launcher to the matching application. Profiles remain independent of the exported skill; opening an older application does not change the launcher.
- Added checks for missing applications, PATH conflicts and modified launchers. Windows registration preserves existing PATH entries and supports removing a launcher that is still running.

### Save before stopping

- **Stop session**, including the close-window option, now attempts a normal game save before finalizing recording and stopping the runtime.
- If saving is unavailable or cannot be confirmed, choose **Stop without saving** or **Cancel**. Cancel keeps the paused game, viewer and recording open; agent control has been released.
- The host CLI `astrabridge stop` also saves first. On failure it keeps the runtime open; use `stop --without-save` or `stop --cancel` explicitly.

### Update

Update the runtime from the new application. Then enable the CLI command and export the gameplay skill once to adopt the permanent launcher. Re-export later when the skill instructions change; changing the application's filename alone no longer requires it.

Downloads: Linux x86_64 AppImage and Windows x86_64 portable ZIP. See the [installation guide](https://github.com/incident201/AstraBridgeForOpenMW/blob/v0.3.1/README.md) and [system requirements](https://github.com/incident201/AstraBridgeForOpenMW/blob/v0.3.1/docs/system-requirements.md).
