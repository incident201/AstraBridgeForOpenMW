## AstraBridge 0.3.0 release candidate 10

### Smaller subsequent runtime updates

- Distribution dependencies now use a frozen base image shared across releases, including when CI build caches expire. Dependency refreshes are explicit.
- Python dependencies, FFmpeg, MediaMTX, OpenMW, Bridge code and release metadata are stored in separate image layers. Unchanged components are reused during updates.
- Layer timestamps are normalized, Python bytecode is excluded from the dependency layer, and staging starts clean to avoid unnecessary layer changes or leftover files.
- **The first update to this image layout may still download most of the runtime.** Smaller downloads apply to subsequent updates when components are unchanged.

### Visible download progress

- Setup now shows downloaded bytes, transfer speed, reused data, completed layers and elapsed time.
- Download completion is separate from backup, container replacement and health-check stages.
- When byte counters are unavailable, the UI shows an indeterminate indicator and elapsed time instead of a guessed percentage. Extended gaps in progress are shown explicitly.
- The installation log remains available in an expandable section.
- Linux checks for `script` from util-linux and `stty` from coreutils, used to obtain native Podman progress counters without a graphical terminal.

### Downloads and update

- **Linux:** download the x86_64 AppImage and make it executable.
- **Windows:** extract the portable ZIP and run `astrabridge.exe`.
- Open the new application and update the runtime in Setup. A normal update preserves managed data.
- Runtime: `ghcr.io/incident201/astrabridge-runtime:v0.3.0-rc10`. Its exact digest is embedded in Desktop and recorded in `release.json`.

Supply your own Morrowind installation. See the [system requirements](https://github.com/incident201/AstraBridgeForOpenMW/blob/v0.3.0-rc10/docs/system-requirements.md). `SHA256SUMS` covers the application packages, release metadata and source archive. This is a pre-release.
